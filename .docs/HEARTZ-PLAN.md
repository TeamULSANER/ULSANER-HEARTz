## 1. 페인포인트와 문제 정의

- 이촌을 지나던 운전자가 20년 전 아내에게 프러포즈한 날을 떠올린다. “오늘 꽃이라도 사들고 가야겠네요.” 누군가에게 들려주고 싶지만, 그 기억을 붙잡아 둘 수단이 없으면 지나가는 생각으로 남는다.
- 다른 사람도 각자의 이유로 그 길을 지난다. 라디오처럼 짧은 사연을 즐겨 듣는 사람에게 **지금 눈앞에 있는 곳에 얽힌 이야기가 들리는 경험**을 제공한다.
- Heartz는 누군가 장소에 남긴 짧은 음성 사연을, 그곳을 지나는 운전자와 동승자에게 편지로 건네는 Pleos 앱이다. 이름은 라디오 주파수 **Hz**와 사람들의 마음 **Hearts**를 함께 떠올리게 한다.
- 제품 가설은 **같은 음성도 그 장소에서 들으면 더 마음에 남고, 청취자가 자신의 기억도 남기고 싶어진다**는 것이다. 실제 효과는 청취 실험과 파일럿으로 검증한다.
- 장소에 음성을 붙이는 Echoes·MemoryLane, 주행 중 주변 이야기를 들려주는 Passenger Seat, 현대차의 이전 수상작 창밖동화가 있다. Heartz는 **실제 사람의 짧은 일상 사연이 기본 내비 옆에 편지로 도착하고, 청취자가 원할 때 열고 같은 장소에 답장을 남기는 흐름**으로 차별성을 검증한다. [Echoes](https://www.echoes-app.com/) · [MemoryLane](https://play.google.com/store/apps/details?id=emergingevidence.memorylane) · [Passenger Seat](https://www.passengerseat.app/how-it-works) · [창밖동화와 이전 수상작](https://www.hyundaimotorgroup.com/ko/story/hyundai-motor-company-pleos-connect-app-idea-contest)

## 2. 타깃 사용자

| 구분 | 정의 |
| --- | --- |
| 핵심 청취자 | 차량 이동 중 사람들의 짧고 소소한 이야기를 들으며 웃거나 공감하거나 위안을 얻는 것을 좋아하는 운전자와 동승자 |
| 작성자 | 장소에 얽힌 기억을 자기 목소리로 간직하거나, 그곳을 지날 사람과 나누고 싶은 사람 |
| 첫 실험 참여자 | 일상 사연을 즐겨 듣는 사람. 실험 구간은 팀이 사연을 모으고 주행을 재현하기 쉬운 곳으로 선정 |

혼자 운전하는지, 같은 길을 반복하는지, 이동 목적이 무엇인지는 타깃의 조건이 아니다. 한 구간은 콘텐츠와 재생을 검증하기 위한 파일럿 범위다.

## 3. 핵심 UX와 기능 우선순위

### 청취

1. 사용자가 Heartz를 열고 기본 내비와 나란히 배치한다. 목표 시연은 시스템 주행 정보 영역, 내비, Heartz 창이 한 화면에 있는 모습이다. 창 배치는 Pleos가 관리한다.
2. 지원 구간에 접근하면 Heartz 창 안에 **이촌에서 온 사연**과 보낸 사람을 표시한다. 사연지는 사연마다 파랑·주황·노랑·초록 중 하나로 고정해 보여 주고(감정 분석 도입 전 임시), 주행 중에는 정적인 카드로 표시한다.
3. (2026-11-11 피드백 반영) 주행 중 `사연이 오면 바로 읽어 주기`(기본 켜짐)이면 묻지 않고 "OO에서 사연이 도착했어요. 읽어드릴게요."라고 알린 뒤 바로 읽는다. 다 들으면 공감 하트를 묻고, 하트를 남기면 "사연자님께 마음이 전달되었어요."라고 말한다. 읽는 중 다른 장소의 사연이 오면 줄을 세웠다가 공감을 정한 뒤 "이번에는 OO에서 사연이 도착했어요. 읽어드릴게요."로 이어 읽는다. 앞 사연을 닫은 지 10초 안에 온 사연도 "이번에는"으로 알린다. 주차 중에는 사용자가 고를 때만 재생한다. 재생·일시정지는 플랫폼이 허용하는 상태와 조작 방식에 맞춘다.
4. 내비 안내·통화 등은 Pleos 오디오 포커스 정책에 따른다. 앱은 재생을 끝내거나 중단할 때 포커스를 반납한다. 음악과 순정 FM의 복귀 동작은 각각 AVD에서 확인한다.
5. 실제 표시됐지만 듣지 않은 사연은 주차 후 `지나온 사연`에서 볼 수 있다. (탭 이름: 지금 이 길 / 지나온 사연 / 남기기 / 내 사연함 / 설정. 앱 화면·안내에서 "편지" 대신 "사연"을 쓴다.)

### 작성과 보관

| 경로 | 위치 연결 | 작성·전송 |
| --- | --- | --- |
| **주차 후 녹음** | 작성자가 공개 장소나 사연이 열릴 곳을 직접 선택한다. 녹음한 곳과 이야기의 장소는 달라도 된다. | 녹음, 잡음 줄이기, 미리 듣기(마음에 안 들면 다시 녹음), 목소리 선택(내 목소리/변조 목소리), 검수에 보내기. `내 사연함`에서 바로 확인한다. |
| **지나면서 녹음** | 명시적인 녹음 시작 시점의 최신 유효 위치를 임시로 저장한다. 종료할 때의 위치로 바꾸지 않는다. | 플랫폼에서 지원과 허용 범위를 확인한 입력으로 시작·종료한다. 녹음을 마치면 "이 사연을 전달할까요? 다시 녹음하려면 '다시'라고 말해 주세요." → "원하시면 변조 목소리로 사연을 전달할까요?"를 묻고, 보내면 검수 대기열로 보낸다(주행 중에도 다시 녹음 가능). 주행 중 전송 경로를 확인하지 못했거나 네트워크·위치가 불안정하면 초안으로 보관하고 주차 후 이어간다. |
| **음성 답장** | 원글의 장소에 연결한다. | 주차 후 `나도 여기서…`로 10~20초 답장을 남긴다. 원글 작성자가 답장을 허용한 경우 한 단계만 제공하며, 원글과 동일하게 검수한다. 첫 버전에서는 주차 후 골라 듣는다. |

- **공개 범위**는 하나다(2026-11-11): 보내면 `검수 중` → 승인되면 `공개`. 나만 보기·나만 듣기는 없앴다(예전 데이터는 `보내지 않음`으로 보이고 검수에 보낼 수 있다). 반려는 운영 상태로 남는다.
- **목소리**(2026-11-11): 사람의 목소리로 연결되는 경험이 핵심이라 기본은 녹음한 목소리 그대로 전한다. 작성자가 원하면 **변조 목소리**를 고를 수 있고, 이때 받는 사람에게는 받아쓴 글을 Pleos TTS로 읽어 준다(원본 녹음은 작성자·운영자만 들음, 받아쓰기가 없으면 승인할 수 없음). 원본 녹음은 저역 차단·스펙트럼 차감·음량 맞춤으로 잡음을 줄여 사연자 목소리가 잘 들리게 한다. LLM 다듬기·음성 복제는 플랫폼 제약(앱용 LLM SDK 미공개)과 난도 때문에 쓰지 않는다.
- **분위기**는 화면에서 뺐다(2026-11-11). 지금은 사연마다 임의의 색(파랑·주황·노랑·초록)을 고정해 사연지·목록 봉투에 쓴다.
- **MVP**는 위치 기반 제안, 선택 재생, 주차 후 녹음, 내 사연함, 공개 제출·승인, 두 번째 사용자의 수신이다. 음성 답장과 지나면서 녹음·전송은 이 흐름 위에서 개발하며, 주행 녹음은 6절 통과 조건을 충족할 때 활성화한다.
- **후속 범위**는 친구끼리 듣기, 배경음, 게스트 시즌, 결제·음색 팩, 실제 앰비언트 제어다.
- **향후 개발: 감정 분석 → 앰비언트 라이트** — 감정 분석 모델을 도입해 사연의 분위기(따뜻함·그리움·유쾌함·담담함 등)를 분류하고, 분위기별 색을 매핑한 뒤, 사연을 읽어 줄 때 그 색으로 차량 앰비언트 라이트를 맞춘다. 분류 결과는 작성자가 고칠 수 있게 하고, 조명 제어는 Vehicle Control 권한·차종 지원·실제 상태 변화(readback)를 확인한 뒤 명시적 설정으로만 켠다. 그 전까지 화면 색은 임의 배정이다.
- **향후 개발: Pleos 프로필 연동**(2026-11-13 결정). 아이디어는 차량에 로그인한 Pleos 프로필 이름을 HEARTz 닉네임으로 쓰고, 프로필을 바꾸면 닉네임도 따라가게 하는 것이다. 지금은 구현할 수 없다. 공식 SDK에 앱용 프로필 API가 없다. 차량 Android 사용자 이름을 읽는 `UserManager.getUserName()`은 일반 앱에서 `SecurityException`을 낸다(`QUERY_USERS`는 signature|privileged|role 권한). Resources 문서에는 "cloud-managed driver profiles"가 향후 지원 예정으로만 나온다. 공개 API나 권한이 생기면 다음 순서로 추가한다. ① 로그인할 때 이름을 읽는다. ② 못 읽으면 저장된 이름을 그대로 쓰고, 지어낸 이름은 쓰지 않는다. ③ 운영자 계정은 바꾸지 않는다. 그 전까지 닉네임은 계정에 저장된 이름이고, 화면의 프로필은 Pleos 상태 표시줄 모양(첫 글자 원)만 따른다.

## 4. 편성, 프로필, 검수

### 편성

1. 공개 승인된 원 사연만 후보로 삼는다. 지금 지나는 구간에 해당하고, 아직 듣지 않았으며, 사용자가 숨긴 작성자의 사연이 아닌지 확인한다. 후보 구간은 시연 데이터에서 직접 지정한다. 물리적으로 가깝지만 다른 도로의 사연이 뜨는지는 별도로 시험한다.
2. **초기 선택은 조건을 통과한 후보 사이에서 무작위로 한다.** 품질 순위나 인기도 점수는 도입하지 않는다. 후보 적격성 판정과 무작위 선택을 나눠 구현해 테스트에서 결과를 재현할 수 있게 한다.
3. 출시 후 데이터가 쌓이면 신규 사연과 노출이 적은 사연의 기회를 넓히는 편성 규칙을 시험한다.

### 프로필과 공개 범위

- 운영 방향은 **Heartz의 작성자 프로필을 기반으로 한 실명제**다. 실명 확인 수단, 공개 화면 표시 범위, 확인 데이터 보관 여부는 출시 설계에서 확정한다. 신원 확인과 실명의 공개 노출은 별도 결정으로 취급한다.
- 개발·시연은 명시적인 테스트 계정과 테스트 이름을 쓴다. 실명 확인을 구현한 것처럼 표시하지 않으며, 실사용자의 신분증·주민등록번호 등은 MVP에서 수집하지 않는다. 실명제는 사전 검수나 신고 기능을 대체하지 않는다.
- 사연의 장소를 표시하는 데 필요한 좌표 또는 장소 ID만 전송한다. 연속 주행 경로는 서버로 보내지 않는다. 주행 녹음 시 임시 위치는 공개 전에 공개 가능한 장소로 연결하고, 공개 카드에 개인 주소나 원본 GPS 값을 노출하지 않는다.

### 검수

- **운영 흐름**은 `초안 → 검수 대기 → 승인 또는 반려`다. 승인한 사연도 이후 숨김 처리할 수 있다. 개인 보관함과 공개 피드는 상태·권한으로 분리한다. 작성자는 자신이 남긴 사연을 확인할 수 있고, 공개 피드와 공개 재생 URL은 승인 상태를 서버에서 검사한다.
- 공개 전 운영자가 원본 음성을 들어 장소 관련성, 음질, 갑작스러운 큰 소리, 장난성 반복 음성, 개인정보 노출, 괴롭힘을 확인한다. 원글과 답장에 같은 기준을 적용한다. 금칙어 하나로 맥락 있는 사연을 막지 않는다.
- AI 음성 전사와 의심 구간 표시가 준비되면 검수 우선순위를 돕는 데 쓴다. 첫 공모전 경로는 사람 승인으로 작동한다. 전사 실패는 자동 승인 사유가 아니다.
- 주차 후 신고와 작성자 숨기기를 제공한다. 사용자 숨기기는 즉시 해당 사용자에게 반영하고, 신고는 운영자가 검토한다. 승인 취소된 음성은 이후 공개 응답에서 제외하고, 앱이 다음 동기화 시 캐시를 갱신한다.

## 5. 기술 구조와 최소 데이터 계약

**차량 앱**은 Kotlin·Compose와 Media3 기반으로 시작한다. 한 앱 모듈 안에서 위치 입력, 편성, 재생, 녹음, 저장을 서로 교체할 수 있게 분리한다. 위치의 우선 후보는 `NaviHelper`, 주행 UX 제한의 기준은 `CarUxRestrictions`다. 실제 플랫폼 허용 상태를 반영하고 기어 값 하나로 UI 제한을 대체하지 않는다. [NaviHelper 공식 샘플](https://github.com/Pleos-Playground/pleos-sample-navi-app) · [NaviHelper 이벤트](https://document.pleos.ai/en/api-reference/connect-sdk-pleos/NaviHelper/event-listeners) · [Pleos 주행 규제 개발](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)

- **위치 입력**은 실제 SDK 경로와 테스트 경로를 구분한다. 값이 없거나 오래됐거나 서비스가 연결되지 않으면 위치 성공으로 처리하지 않는다. 창 크기 변경과 앱 화면 전환 시 위치 구독과 재생의 생명주기를 검증한다.
- **미디어**는 재생·일시정지·종료와 포커스 처리를 구현한다. 시스템 미디어 통합은 해당 Pleos Music/Audio 가이드의 현재 요구사항을 확인해 맞춘다. 카드 표시와 음성 재생을 분리해, 위치 이벤트 자체가 소리를 내지 않게 한다. [Pleos Music/Audio 개발 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/music-audio-app-developement-guide)
- **로컬 단계**는 사용 허락을 받은 음성 3개와 장소 메타데이터로 동작하게 만든다. **두 사용자 단계**는 기존 백엔드가 있으면 재사용하고, 없으면 앱에 비밀키를 넣지 않는 최소 API·저장소를 선택한다. 공모전 데모는 테스트 사용자 두 명과 검수 역할 한 명이면 된다.
- **구현 계약**은 아래 표를 기본으로 기존 모델과 합친다. 서버는 업로드 성공, 공개 제출, 승인, 공개 재생 가능을 서로 다른 결과로 반환한다. 재시도 시 동일 초안이 중복 공개되지 않게 한다.

| 모델 / 기능 | 최소 항목 및 결과 |
| --- | --- |
| `Place` | `id`, 표시명, 승인된 공개 위치, 편성에 사용할 구간 설정 |
| `Story` | `id`, 작성자 ID, 장소 ID, 오디오 참조, 길이, 분위기, 공개 범위, 검수 상태, 생성 시각, 선택적인 `parentStoryId` |
| `ListenState` | 사용자별 제안·재생 여부, 숨긴 작성자 목록. 원본 주행 좌표 이력은 저장하지 않는다. |
| 조회 / 작성 | 승인된 사연 목록 조회, 개인 보관함 조회, 초안 저장, 공개 제출, 재생 가능한 음원 조회 |
| 운영 | 대기열 조회, 권한을 확인한 승인·반려·숨김, 신고 접수. 일반 계정은 검수 상태를 바꿀 수 없다. |

## 6. 주행 중 녹음·전송 검증 조건

주행 중 그 장소를 지나며 사연을 남기는 경로는 **제품 범위에 포함**한다. 아래 조건을 실제 환경에서 확인한 다음 활성화한다. 첫 심사에 이 경로를 포함할지는 검증 결과로 결정한다.

1. **시작·종료** — 플랫폼에서 사용할 수 있는 명시적 입력으로 시작하고 끝낸다. 운전자에게 주행 중 키보드, 지도 선택, 녹음 편집, 공개 확인 화면 조작을 요구하지 않는다. 권한 요청과 공개 범위 사전 설정은 주차 중 완료한다. 위치 진입만으로 녹음이 켜지지 않는다.
2. **마이크** — AVD에서 Heartz 자체가 접근 권한을 얻고 음성 파일을 생성하는지 확인한다. Pleos의 AVD 마이크 설정 안내가 있다는 사실과 해당 APK에서 실제 마이크가 작동한다는 사실을 구분한다. 통화·음성 비서 등과 충돌하면 권한·포커스 상태에 맞게 녹음을 중단하거나 보류한다.
3. **위치** — 녹음 시작 시점의 위치가 유효한지 확인하고, 앱은 그 값을 임시 장소로 묶는다. 실제로 지나지 않은 곳을 자동 지정하지 않는다. 위치가 없거나 공개 장소 연결을 확정할 수 없으면 초안으로 남긴다.
4. **전송** — 허용된 입력으로 사용자의 명시적 공개 제출 의사가 확인되면 서버 검수 대기 상태까지 검증한다. 재생 후보는 승인 후에만 된다. 공개 의사가 확인되지 않으면 개인 초안으로 저장한다.
5. **연동 범위** — Gleo는 앱 액션 호출 경로의 후보다. Gleo가 사용자 발화의 원본 오디오를 Heartz에 넘겨주거나, Gleo 음색을 앱 TTS로 제공한다고 가정하지 않는다. 앱 녹음·주행 중 명령·전송 중 확인하지 못한 기능은 주차 후 흐름으로 제공하고 시연에서 상태를 구분한다.

## 7. 초기 콘텐츠, 효과 검증, 사업 모델

- **초기 공급** — 출시 전에 “이 길을 지나면 누가 생각나나요?”로 사연을 모은다. 학교나 동네 한 구간의 공개 장소 3곳에 승인된 12~18편을 확보하는 것을 운영 목표로 둔다. 모바일 응모와 지역별 사연 이벤트로 작성자를 모은다. 성과는 응모 수와 함께 실제 편성 가능한 편수로 확인한다.
- **청취 실험** — 위치 맥락 없이 들려준 조건과 해당 장소를 지나는 화면에서 들려준 조건을 비교한다. 제시 순서를 나눠 보고, 장소가 더 기억에 남았는지·자기 이야기가 떠올랐는지·다음 차량 이동에서 다시 열고 싶은지 확인한다.
- **파일럿 지표** — 첫 이동에서 편지를 본 비율, 카드 표시 후 재생 비율, 다음 차량 이동에서 다시 연 비율, 청취 후 사연 또는 답장을 남긴 비율을 본다. 검수 처리 시간과 승인 사연 확보량도 함께 본다.
- **기관 고객 가설** — 지역 문화기관, 지방문화원, 지역 라디오에 ‘우리 동네 편지 시즌’을 제안한다. 초반에는 사연 모집·검수·편집·편성·운영 결과를 포함한 시즌 단위 제작비를 검증한다. 재계약 요청이 확인되면 기관 운영 도구와 채널 운영료를 시험한다. 유사한 지역 구술 기록 사업 사례는 있으나 Heartz의 구매 의사는 검증 전이다. [한국문화원연합회 구술 기록 사례](https://www.kccf.or.kr/bbs/detail.do?bbsId=N000000000000000000018&nttId=B202411260111503165451&selMenuId=MK0058)
- **개인 수익화** — 공개 청취와 짧은 공개 사연 작성은 무료로 시작한다. 친구·가족 편지가 반복 사용되면 긴 개인 편지와 이용 권리를 확보한 낭독 음성 팩을 시험한다. 지불 여부로 승인이나 추천 순위를 바꾸지 않는다.
- **확장** — 지역 채널을 한 곳씩 추가하고, 친구는 차량 프로필이 아닌 Heartz 계정으로 연결한다. 연예인·창작자가 실제 사연을 남기는 게스트 시즌과 장소별 편지 투어를 시험한다. 유명인·캐릭터 음성, 배경음은 필요한 이용 권리를 확보한 뒤 제공한다. 앰비언트 라이트는 Vehicle Control 권한·차종 지원·동작을 확인한 뒤 별도 단계에서 다룬다.

## 8. 개발 순서와 완료 기준

| 단계 | 구현 | 완료 기준 |
| --- | --- | --- |
| **M0 · 기술 검증** | 기존 앱 또는 공식 샘플을 실제 Pleos AVD에 실행. 기본 내비와 나란히 띄운 상태에서 좌표와 주행 제한을 확인 | 입력 좌표 변경과 실제 앱 수신 로그를 구분해 기록한다. 내비 안내 활성 여부에 따른 차이, Heartz가 보이지만 소리를 내지 않을 때의 수신, 재생 포커스 동작을 확인한다. 실패하면 환경·권한·서비스와 관측 결과를 기록한다. |
| **M1 · 한 통의 편지** | 시드 오디오, 구간 후보 판정, 무작위 선택, 분할 창의 카드, 명시적 재생 | 실제 SDK 경로로 구간에 접근하면 조건에 맞는 카드가 표시된다. 버튼을 누르기 전 사연 음성은 나오지 않는다. 재생·중단과 주행 제한 상태를 AVD에서 확인한다. |
| **M2 · 작성과 공개 순환** | 주차 후 녹음·장소 선택, 내 사연함, 테스트 계정, 공개 제출과 운영자 승인, 두 번째 사용자의 재생 | 개인·대기·반려 사연은 다른 계정에서 공개 목록과 음원으로 접근할 수 없다. 승인 후 두 번째 계정이 같은 구간에서 해당 사연을 받아 선택 재생할 수 있다. 답장은 같은 녹음·검수 흐름을 재사용한다. |
| **M3 · 지나면서 녹음** | 6절에 따른 마이크·음성 명령·위치 고정·명시적 제출 검증 | 녹음 시작 지점이 유지되고, 취소·권한 실패·통화·네트워크 오류에서 공개 상태로 잘못 전환되지 않는다. 허용 조건을 확인한 경로만 활성화한다. |

- **검증 시나리오** — 구간 안/밖, 후보 없음, 검수 대기 음성, 이미 들은 음성, 숨긴 작성자, 복수 후보, 창 크기 변경, 내비·통화에 따른 오디오 중단, 주행 제한 변화, 업로드 실패·재시도, 승인 권한 오류를 확인한다.
- **실패 시 진행** — AVD나 위치 SDK가 막혀도 분할 화면 레이아웃·편성 규칙·검수 상태·재생 로직을 로컬 테스트로 진행한다. 테스트 경로는 개발용으로 분리하고, 직접 주입한 값으로 SDK 연동이 확인됐다고 보고하지 않는다. GPX/좌표는 에뮬레이터 입력을 재현하는 수단이며 실제 위치 연동은 앱에서 받은 콜백으로 확인한다.
- **작업 기록** — 어떤 빌드와 AVD에서 무엇을 실행했는지, 실제 SDK에서 확인된 항목, 시드/테스트로만 검증한 항목, 미검증 항목을 나눠 남긴다. 실차와 DevBox가 없으므로 이 결과를 실차 검증으로 표기하지 않는다.
